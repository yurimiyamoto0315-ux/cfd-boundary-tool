アーキトレンド 出力データ

CSVを主入力として窓と外皮面積を正確に取得します。PDFを追加すると、CSVにないUA・U値・居室・窓ηなどを補完して相互検証します。

CSVのみでも窓は取得できます。部屋カードはPDFがある場合のみ居室を作成し、廊下・水回り・収納等は除外します。3DSは内壁の無い外皮です。方位色分けし庇を除き、屋根の上を埋めます。メッシュはブラウザに保存しないので、開き直したら選び直してください。

    EnergyPlus IDF / SQL / EPW

    部屋別モデルの IDF を主入力にします。床下・小屋裏ゾーンは除外し、居室の外壁面積・熱貫流・窓U・UA・外皮面積と、People の最大在室人数を入れます。SQL (eplusout.sql) は任意・推奨で、冷房ピークの日付と時刻に加え、Hourly の面日射があれば Grasshopper と同じ SAT/ETD と窓の透過日射を使います。EPW は SQL に外気温が無いときの控えです。換気回数は 0.5 回/h、床・基礎Uと人体・機器の原単位は初期値が入っています。

    SAT/ETD には SQL の面入射日射 (Hourly)、窓の有効熱取得には透過日射 (Hourly) が必要です。時系列はブラウザに保存しないので、開き直したら SQL と EPW を選び直してください。在室人数は IDF の People（最大人数）から入れ、People が無い室は 0 人です。

      いま · Step 1-4 SAT
      相当外気温度 (SAT: Sol-Air Temperature) とは
      壁や屋根など日射が当たる不透明な外皮表面は、外気温だけでなく日射も受けて温められています。SATは、その「外気温+日射の影響」をまとめて1つの仮想的な外気温として置き換えたものです。
      SAT = 外気温 Ta + α×(壁面が受ける日射量)/外表面熱伝達率 ho − (屋根のみ) 夜間放射による低下分。
      EnergyPlus の SQL に面日射があるときは、この SAT を ISO 13786 の遅れ φ と減衰率 η で ETD にし、発生パネルの外気温は 室温 + ETD とします (q = U × ETD)。SQL が無いときは従来どおり晴天モデルの SAT を外気温に入れます。

      いま · Step 1-7 窓の疑似厚み
      疑似厚みとは — 厚み0のパネルに、仮想の厚みで熱抵抗を持たせる
      FlowDesigner上の窓は「発生パネル」、つまり厚みを持たない面 (厚み0のパネル) としてモデル化します。厚み0のままではガラスとしての断熱性能 (熱抵抗) を表現できないため、「厚みを考慮 = はい」にして材質と疑似厚みを入力します。するとCFDは、そのパネルがあたかもその厚みの材質でできているかのように熱抵抗 (= 疑似厚み ÷ 材質の熱伝導率λ) を計算してくれます。
      つまり疑似厚みは実際のガラス厚ではなく、窓全体の熱貫流率U (カタログ値) と同じ熱抵抗になるように逆算した仮想の厚みです。日射熱はここでは入れず、Step 2の内部発熱ボリューム側で計上します。

      1-7 窓 (疑似厚みの逆算)

      躯体のみの熱抵抗 = 1/U − 1/外表面 − 1/内表面、疑似厚み = 躯体熱抵抗 × λ。EnergyPlus連携では各窓のUを部屋カードに入れ、ここは面積加重の代表値です。種類が複数あると下表と3DS色分けで疑似厚みを分けます。日射は各窓のη0です。

      02Internal Gains内部発熱と直達日射（部屋ごとの発生エリア）

      いま · Step 2 内部発熱+直達日射

      部屋の中では「人がいること」と「日射が入ること」自体が熱源になります。この2つ (+機器) の発熱・発湿を合計してStep 3で使います。

      日射計算のしくみ (このツール内部の計算)

      上に表示した「直達日射 I_DN」「太陽高度角」「太陽方位角」は、共通条件の日付・時刻・緯度経度から次の4段階で計算しています。各窓の直達日射 (W) は最後の式で決まり、Step 2の合計に加算されます。

      ① 太陽位置 (高度角 h ・ 方位角 A)
      緯度・経度・日付・時刻から赤緯と時角を計算し、太陽の高さ (高度角 h) と向き (方位角 A、南=0°・東=−90°・西=+90°) を求めます。
      ② 直達日射 I_DN (晴天モデル)
      I_DN = 1098 × exp(−0.057 / sin h) [W/m²]。太陽が低い (朝夕) ほど大気を長く通過して弱まり、高い (南中前後) ほど強くなります。高度角 h が0°以下 (日没後・日の出前) は0として扱います。
      ③ 窓面への入射角 θ
      窓に垂直な向き (法線) と太陽光線のなす角 θ を、高度角 h・太陽方位角 A・窓の向き wAz から求めます (窓は鉛直面として計算)。
      cosθ = cos h × cos (A − wAz) → 窓が受ける日射 = I_DN × max(cosθ, 0)。裏を向いていて cosθ が負になる場合や、真北向きの窓 (このツールの簡略化ルール) は0として扱います。
      ④ 透過率 η → 室内への熱 (W)
      窓ガラス+付属部材 (ブラインド等) を通過する割合を日射熱取得率 η0 として窓ごとに設定します (下の窓入力欄)。最終的な直達日射による室内発熱は次の式です。
      q_eff = q_raw × [f_c + (1−f_c)×r_G] ← この値がStep 2の「直達日射」として部屋ごとに合算されます。
      q_raw は、SQL に透過日射があればその値 (W)、無ければ I_DN × cosθ × η0 × A です。r_G は表2.12の方位×時刻（北面は1.0）、f_c の初期値は 0.10 です。

      屋根・外壁のSAT (Step 1) も同じ太陽位置とI_DNを使い、屋根は水平面、外壁は鉛直面として、それぞれの向きのcosθで日射量を計算しています。

      部屋ごとにボリューム (発生エリア) を作成し、直達日射+人体+機器の発熱・発湿の合計を入力します。太陽条件は共通条件から自動計算されます。この合計はStep 3 (エアコン) の必要処理熱量の計算にそのまま使われます。

      EnergyPlus連携では在室人数を IDF の People（スケジュール前の最大人数）から入れます。People が無い室は 0 人です。人体顕熱・発湿はその人数×原単位、機器は床面積×原単位です。各窓のη0はSHGC、Uは構成から入れます。SQLに透過日射があればそれを r_G 補正して使い、無ければ η0×日射×面積に r_G を掛けます。SQLからピーク日付・時刻も入れます。
      対象とする部屋: 居室、および北面以外に窓がある非居室です。真北向きの窓はこのツールの簡略化ルールとして直達日射0 Wで除外します (北東・北西は計算対象)。

      未割当の窓 (アーキトレンド自動取得)要手動

      CSV/PDFから窓ID・面積・方位・ηを自動取得済みです。居室に加えて廊下・水回り・収納等も割当先に選べます。非居室は割当時に自動作成され、人体・機器発熱0、窓の直達日射のみを部屋の発熱量へ加算します。真北向きの窓は直達日射0として割当対象から除外します。

      いま · Step 3-4 / 3-5 吹出温度

      吹出温度 = 目標室温 − (必要処理熱量 ÷ 台数) / (ρ・cp・1台あたり風量)。全台が同じ風量で負荷を均等分担すると仮定しています。

      吹出湿度は業界慣行として95%RH固定です。吹出温度だけが台数・風量で変わります。
      吹き出した流量・温度が住戸全体に行きわたらない場合、処理熱量を満たしていても目標温度に達しないことがあります。そのときは吹出温度を変えて再解析します。

      3-4 吹出温度の算出 (全台数で均等に処理する前提)

      吹出温度 = 目標室温 − (必要処理熱量 ÷ 台数) / (ρ・cp・1台あたり風量)。すべての台数が同じ風量で稼働し、負荷を均等に分担すると仮定しています。

      3-5 台数を変えた場合の比較 (均等分担)

      同じ機種・同じ風量ノッチのまま台数だけを変えたら、1台あたりの処理熱量と吹出温度がどう変わるかの一覧です。現在選択中の台数の行を強調表示します。
