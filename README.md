# CFD境界条件自動化ツール

建物形状・外皮性能・生活条件から、FlowDesignerに渡すCFDモデルと境界条件の作成を補助するツールです。竹内君との共同開発では、**Rhino／ARCHITRENDの3DSデータを起点にEnergyPlusの解析設定・IDFを作り、各自で実行した計算結果をCFDへ連携するフロー**の整備を目指します。

- **確認日:** 2026-10-21。以下の現状は、このフォルダ内のコードを確認した内容です。
- **開発引継ぎ:** 経緯・実装箇所・今後の優先課題は [HANDOVER.md](HANDOVER.md) を参照してください。
- **ローカルEP連携の操作:** 既存の試作機能の詳細は [PIPELINE_README.md](PIPELINE_README.md) を参照してください。

> [!IMPORTANT]
> **標準フローは境界条件設定 → IDF保存 → 各自でEnergyPlus実行・SQL作成です。** `BoundaryTool.vbs` をダブルクリックして起動します。CMDの起動・コマンド入力は不要です。入力作成用のPythonサービスは裏で動作します。

## 現在できること

入力方法とEP計算の扱いが異なる、次の機能があります。

| 機能 | 入力と処理 | 現状・制約 |
| :--- | :--- | :--- |
| CFDのみ：手動／ARCHITREND | 手動値、3DS、温熱CSV・PDFからSAT／ETD・疑似厚み・内部発熱・吹出条件等を作成 | 色分け3DS・SSL用CSVを使ってFD入力を補助 |
| CFDのみ：計算済みEPデータ取込 | 既存IDFを読込み、SQL・EPWで冷房ピーク時刻や気象・面日射等を補完 | 従来の境界条件計算に利用。EP表面温度を直接渡す連携とは処理が異なる |
| EP → CFD：IDF作成 | Rhino書出JSON／ARCHITRENDの部屋候補から熱モデルを作り、24.2用IDFを保存 | IDF作成にEnergyPlusは不要。Python 3.11以上とShapelyが必要 |
| 手動実行SQLの取込 | 各自で作成したSQLを取り込み、時刻を選んでCFD用ZIP出力 | 24.2・8760時間・必要出力を検査。入力IDF・気象の同一性は利用者が確認 |

> [!NOTE]
> 現在のRhino連携は、専用スクリプトで閉じた平面Brep等をJSONへ書き出す方式です。**Rhinoの3DSを直接読んでEPモデルを完成させる機能は未実装**です。ARCHITRENDも部屋形状を候補として再構成するため、面の所属・隣接・開口・接地条件の確認が必要です。

## 起動方法

### CFDのみを使う

1. **画面を開く:** このフォルダの `index.html` をブラウザで開きます。
2. **入力方法を選ぶ:** 「CFDのみ」で手動・ARCHITREND・計算済みEPデータ取込を選択します。
3. **条件を確認する:** 単位・北方向・部屋・材料・内部発熱・空調条件を確認し、境界条件と3DSを出力します。
4. **FDへ反映する:** 画面内のFDスクリプト配布・導入案内に従い、FDで色対応CSVを出力 → ツールで `objParam.csv` を作成 → FDのSSLスクリプトで読み込みます。
5. **解析を仕上げる:** 解析領域・メッシュ・空調や換気口の位置などをFDで設定し、解析・収束確認を行います。

> [!NOTE]
> 外部APIや一部ライブラリの取得には通信が必要です。直接開いて読込みに失敗する機能がある場合は、ローカルHTTP配信で確認してください。

### 境界条件を設定してIDFを保存する

1. **起動:** `BoundaryTool.vbs` をダブルクリックします。ブラウザが開いたら「EP → CFD」を選びます。
2. **形状と条件:** 建物JSON、またはARCHITRENDの部屋候補を取り込み、部屋・面・材料・内部発熱・換気・空調スケジュールを確認します。
3. **IDF保存:** 確認チェックを入れ、「IDFを作成・保存」を押します。「入力・対応表・手順をZIP保存」で建物JSON・対応表も保存できます。
4. **手動実行:** EnergyPlus 24.2のEP-Launchで、保存した `model.idf` と年間EPWを選んで実行します。SQL出力の設定はIDFに含まれます。
5. **SQL取込:** 同じIDFの計算が正常終了したこととエラーログを確認して、画面04から `eplusout.sql` を読み込みます。
6. **終了:** 画面右上の「ツールを終了」で入力作成サービスを停止できます。

- **必要環境:** Windows・Python 3.11以上。初回はShapelyを `.python-deps/` へ導入します。Pythonを自動検出できなければ `BOUNDARY_PYTHON` に実行ファイルを指定します。
- **接続先:** `http://127.0.0.1:8766/`。ブラウザだけを閉じた場合はサービスが残り、次回起動時に再利用します。
- **担当範囲:** ツールはEnergyPlusを起動しません。気象の選択・計算・SQL作成は利用者が行います。モデルはIdealLoadsによる必要負荷計算で、実機エアコンの消費電力計算ではありません。

## イラスト付きの「かんたん設定」

**画面03は、建物・部屋・生活・確認の4段階で進めます。** 専門的な項目は「詳しく設定する」にまとめています。

1. **建物の仕様:** SVGで外壁・屋根・床・窓の役割を確認し、必要なら例の断熱仕様や窓の値を適用します。
2. **部屋の使い方:** 部屋ごとに名前・空調の有無・人数・照明・家電・換気を確認します。
3. **暮らしと空調:** 在宅時間の例、暖冷房の設定温度、空調の運転時間を選びます。
4. **確認して保存:** 設定の要約を確認し、確認チェックを入れて画面04でIDFを保存します。

- **ARCHITREND連携:** CSV／PDFから読んだ外皮・窓の性能、対応する部屋情報を自動反映します。画面03に反映件数・出典・未取得項目を表示します。変換の前提は [PIPELINE_README.md](PIPELINE_README.md) を参照してください。
- **既存設定の保持:** 画面を開いたりステップを切り替えたりしても、入力済みの値は変更しません。例の値は適用を選んだ場合に反映します。
- **仮定値の扱い:** プリセットは計算を始めるための例です。実際の仕様・人数・設備・換気計画に合わせて確認してください。
- **詳細編集:** 材料層、室内発熱の放射比、漏気、空調の月日期間、24時間の個別スケジュールも従来どおり編集できます。

## 標準フローと今後の拡張

**ツールがEPの入力作成と結果のCFD変換を担当し、EnergyPlusの計算は利用者が各自のPCで行う**構成にします。

1. **形状を取り込む:** Rhino／ARCHITRENDから出力した3DSを読み込み、部屋・外壁・屋根・床・窓・ドア・日除けを整理します。3DSだけでは不足する室区分・材料・隣接関係等は画面で補います。
2. **EPの解析条件を設定する:** 北方向、気象EPW、材料層・窓性能、在室・照明・機器、換気・漏気、空調設定温度・スケジュール、解析期間を設定します。
3. **IDFを出力する:** 対応EnergyPlusバージョンを明記した `.idf` と、部屋・面の対応情報、設定記録、実行手順をダウンロードできるようにします。
4. **各自でEPを実行する:** 利用者が**出力IDFのバージョンに合ったEnergyPlusをダウンロード・インストール**し、同じEPWを指定して計算します。
5. **結果をツールへ戻す:** 同じ実行の `eplusout.sql` を読み込みます。版・年間時間数・必須出力を検査します。入力・気象・ログの自動照合は今後の拡張です。
6. **CFD条件へ変換する:** 冷暖房ピークまたは指定日時の面別表面温度・熱取得・室内対流発熱等を利用して、CFD用3DSと境界条件を出力します。
7. **FDで解析・照合する:** 空調・換気・メッシュを仕上げ、従来フローとの同条件比較、室温・熱収支・実測値との照合で改善を確認します。

> [!WARNING]
> 「最新版のEnergyPlusを入れればよい」という案内にはしません。**IDFの `Version` とツールの対応版を確認し、その版のEnergyPlusを各自で導入してください。** 現行ローカル実装の基準は24.2系ですが、将来の対応版はIDF出力機能とセットで管理します。

- **入手先:** [EnergyPlus公式リリース](https://github.com/NatLabRockies/EnergyPlus/releases)。現行の24.2系を導入する場合は [24.2.0修正版](https://github.com/NatLabRockies/EnergyPlus/releases/tag/v24.2.0a) を参照してください。
- **実行の参考:** [公式Quick Start Guide](https://energyplus.readthedocs.io/en/v24.2.0/quick_start/quick_start.html) に入力IDF・EPWと実行方法の説明があります。
- **版を変更する場合:** 公式の変換手順で入力を更新し、ツールの出力・取込も再検証します。`Version` の数字だけを書き換えて対応済みとはしません。[公式のバージョン更新説明](https://energyplus.readthedocs.io/en/stable/essentials/essentials.html#versions-and-updating)

## EP計算結果を使う目的

**EPの気象・日射・蓄熱・生活スケジュールを反映した熱状態をCFDへ渡し、従来のSAT／ETDや室ごとの一様発熱を使うフローから、境界条件の精度向上を目指します。** その効果は同条件の比較で検証します。

- **外皮・窓:** EPの室内側表面温度を使う場合、その面へ従来のSAT・外気温／熱貫流条件を重ねません。
- **内壁・室間床・天井:** 現行ローカル実装は、材質・疑似厚みで伝熱を計算し、EPの正味放射受熱を材料発熱として渡します。表面温度は固定しません。
- **室内発熱:** 空気への対流分と面への放射・日射を分けます。EPの冷暖房負荷全体を室内発熱に加えません。
- **連成の範囲:** まずEP結果をCFDへ渡す一方向の連携を完成させます。CFD室温をEPへ戻す反復連成は、その後の検討項目です。
